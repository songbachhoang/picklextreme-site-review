PickleXtreme site review

picklextreme.ca (homepage + 20 pages)Checked 21 Nov 2026Desktop 1440×900 · iPhone 375×812

Verdict

Your instinct is right, and most of it is countable now. A first-time visitor gets four attention-grabbers inside 3 seconds: a full-screen tournament popup, a chat widget with three auto-opened bubbles and a red badge, a browser tab that flashes "1 new message", and a 4-item promo ticker. The popup fires on every homepage visit, with no frequency limit.

The homepage is also long: 16 screens on desktop, 29 on a phone, with 24 slide/fade-in animations and 3 autoplaying videos. Page speed is fine. The problem is noise, not load time.

The biggest booking leak isn't the animation, though. Most "Book" links send a new visitor to a CourtReserve login screen before they see a single session (Showdown, clinics, camps, learn to play). Nearby clubs that do better show their schedule publicly. The fix is a public drop-ins & clinics page built from CourtReserve's own widget (below).

What we can't yet say is whether this costs bookings. The site has Google Analytics, but it doesn't record which button people click before they leave for CourtReserve. The plan below adds that tracking and, at the same time, sends 20% of visitors to a calmer homepage built around what's selling now: the tournament and lessons.

The first 3 seconds

  1. 0.0 sTicker (4 promos), nav with 7 menu items + 2 buttons, headline, then 5 booking buttons plus 2 more pill buttons. Desktop shows about 16 clickable choices before you scroll.
  2. ~1 sChat widget loads with a red "1" badge and three pre-written bubbles ("Hi! How can we help?", "I have a question", "Tell me more"). The browser tab title starts alternating with "1 new message".
  3. 2.0 sElementor popup #990954 opens with a dark overlay. Trigger: page load + 2 s. No "show up to N times" rule, so it returns on every homepage visit.
  4. on scroll24 sections slide or fade in (slideInUp ×8, slideInDown ×5, fadeInRight ×5, and others). Three YouTube videos autoplay and loop.

Fix now, no test needed

These are defects, not taste. They go on the live site for both versions in the test, so the test compares calm against busy rather than fixed against broken.

  1. Limit the popup to once per visit. It currently returns every time someone goes back to the homepage. During the test the split script opens it (current version only) and handles the once-per-visit limit, so remove its page-load trigger.Elementor → Templates → Popups → #990954 → Triggers: off. Keep the display condition on the homepage.
  2. Don't lead with a QR code on phones. A phone can't scan its own screen. On mobile, show the flyer image smaller and make "Book now" the main element, or turn the popup off on mobile.Same popup → Advanced Rules → Show on devices.
  3. Stop the chat widget from talking first. Turn off the three auto-opened bubbles, the fake "1" unread badge, and the tab-title flashing. Keep the chat icon itself.tawk.to dashboard → widget appearance and triggers.
  4. Blank white block under each event card on phones. The cards stretch to equal height and leave about 200 px of empty white below the text.Homepage → event loop grid → card container (element 193b79c): remove the fixed height or white background on mobile.
  5. Small copy fixes: "What our clients says" → "What our members say". Contact email still shows club@picklex.ca (old brand). /mississauga-old/ is still in the sitemap; unpublish it or set it to noindex. 6 form fields use text under 16 px, so iPhones zoom in when you tap them.

          : a.closest('[data-elementor-type="header"]') ? (a.closest('.e-con, .elementor-section')?.offsetTop < 60 ? 'ticker' : 'header')
          : a.closest('[data-elementor-type="footer"]') ? 'footer'
          : (a.getBoundingClientRect().top + scrollY < innerHeight ? 'hero' : 'body');
  var txt = (a.innerText + ' ' + a.href).toLowerCase();
  var type = /showdown|tournament|league|dupr/.test(txt) ? 'tournament'

});

The number we judge by

Booking-click rate = visitors with at least one booking_click ÷ visitors who landed on the homepage, split by version, by booking_type (tournament and lessons first, since that's what's selling now) and by phone vs desktop. A click counts wherever it happens, so a lesson booked from the clinics page still credits the homepage version that visitor saw. Register booking_type, cta_location and variant as custom dimensions in GA4. Supporting numbers: mobile scroll depth, popup closed in under 3 s, rage and dead clicks, and CourtReserve's own weekly count of new sign-ups and bookings as a cross-check.

If CourtReserve lets clubs add a GA4 measurement ID to their booking pages, turn on cross-domain tracking and we can count completed bookings instead of clicks. Ask CourtReserve support; until then, clicks are the measure.

A/B test: calm homepage on 20%

The site's main job is booking, and right now that means the tournament and lessons. The test checks one question: does a calmer homepage that leads with those two get more bookings than today's page? 80% of visitors keep the current homepage (A). 20% get the calm one (B). If B turns out worse, only 1 in 5 visitors saw it.

A/B testing keeps a live control group, so there's no need for a separate baseline period. Tracking and the split go live together. B leads with the tournament in the hero instead of a popup, so it can start before the Showdown on 5–6 Dec.

How the split works

A short script in the page head picks A or B once per visitor, remembers it in the browser, and tags every booking_click with the version. CSS classes then show or hide B's pieces. The page address doesn't change, so SEO isn't affected, and WP Rocket's page cache keeps working because the choice happens in the browser.

<!-- Elementor → Custom Code → location: <head>, priority 1, site-wide -->
<script>
(function () {
  var KEY = 'px_exp_calm1', v;
  try { v = localStorage.getItem(KEY); } catch (e) {}
  if (v !== 'A' && v !== 'B') {
    v = Math.random() < 0.2 ? 'B' : 'A';            // 20% calm
    try { localStorage.setItem(KEY, v); } catch (e) {}
  }
  window.pxVariant = v;
  document.documentElement.classList.add(v === 'B' ? 'px-calm' : 'px-current');
  window.addEventListener('load', function () {
    if (window.clarity) clarity('set', 'exp_calm1', v);  // filter recordings by version
    // Version A only: open the tournament popup at 2 s, once per visit
    var seen; try { seen = sessionStorage.getItem('px_popup_seen'); } catch (e) {}
    if (v === 'A' && !seen && window.elementorProFrontend && document.body.classList.contains('home')) {
      setTimeout(function () {
        elementorProFrontend.modules.popup.showPopup({ id: 990954 });
        try { sessionStorage.setItem('px_popup_seen', '1'); } catch (e) {}
      }, 2000);
    }
  });
})();
</script>

End of week 1

Set the end date

Use week 1's visitors and click rate to pick a row in the table, then write down the end date. Run at least 2 full weeks, at most 8.

Decide

Rules for the test

  • Don't stop early because B looks good. With 20% in B, early numbers are mostly noise.
  • One reason to stop early: after 300 visitors in B, its tournament clicks per visitor are below half of A's. That protects Showdown sign-ups.
  • A tie counts as a win for calm. Same bookings with less noise is the better site, and it's easier to keep up.
  • If week 1 shows the test would need more than 8 weeks, move to 50/50, or only look for a big lift (+40%). Don't let it run indefinitely.
  • Don't change the homepage during the test except for the agreed event swap, made the same day in both versions.

The integration: CourtReserve's own widget

  • It already exists. CourtReserve → Settings → "Social Plays & Clinics List" generates an embed code: an iframe plus a small script that sizes it to its content. The club already has one (#58586, clinics and kids camps). I loaded its data with no cookies at all and got 17 sessions back, so it's truly public.
  • It can match the brand. The widget settings include a Custom CSS box, title bar colours, show prices, show remaining spots, hide full sessions, featured only, and "direct to public booking signup".
  • Sign-in only at Register. Visitors browse and filter freely. Register opens CourtReserve, which asks them to sign in or create an account. Payment needs an account anyway.
  • WordPress fit. A new page /drop-ins/ built in Elementor, with the widget code pasted into an HTML widget. One widget per tab: drop-ins & social play, clinics & lessons, kids camps, seniors & Masters. Then point every "Book a clinic / drop-in" link on the site to this page instead of the login screen.
  • WordPress risks are small and known. WP Rocket must not delay the widget's sizing script (it isn't delaying JavaScript today). Iframe lazy-loading is fine. Nothing needs a plugin. Prices and spots stay live because they come from CourtReserve.
